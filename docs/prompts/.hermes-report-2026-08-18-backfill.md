====================================================
TASK 2 — SỬA: progress phản ánh độ phủ THẬT (TDD đỏ→xanh→sabotage)
====================================================
LỰA CHỌN PHƯƠNG ÁN (nêu rõ, không chọn trong im lặng): plan khuyến nghị "ghi last_done_date = ngày bar cuối thật" nhưng cảnh báo "nếu rỗng phổ biến thì mã ít thanh khoản bị fetch lại vĩnh viễn". Task 1 cho thấy rỗng CÓ xảy ra (SDC/MCC) và 945 mã có avg < 100tr → hướng đơn giản sẽ fetch lại ~945 mã mãi mãi. Tôi chọn phương án plan gợi ý: TÁCH HAI KHÁI NIỆM thành 2 cột:
- `attempted_until date` (CỘT MỚI): ngày đã HỎI API tới — ghi LUÔN sau mỗi lần fetch thành công, KỂ CẢ RỖNG. Skip dựa trên cột này (attempted_until >= to → skip) → mã ít thanh khoản KHÔNG bị fetch lại vĩnh viễn.
- `last_done_date` (cột cũ, đổi nghĩa): ngày bar THẬT cuối nhận được — chỉ tiến khi có bar, RỖNG THÌ KHÔNG TIẾN (giữ nguyên giá trị cũ). Đây là cột trung thực, phản ánh đúng độ phủ.

Đánh đổi (nói rõ): bảng thêm 1 cột + ALTER TABLE idempotent trong init_schema (additive, không phá bảng cũ); skip giờ dựa trên attempted_until nên dòng progress CŨ (chưa có cột, NULL) sẽ KHÔNG skip → được fetch lại đúng 1 lần sau khi migration — hành vi đúng mong muốn (mã chưa thực sự đủ dữ liệu phải được thử lại).

File sửa:
- trading/storage/db.py: init_schema thêm `ALTER TABLE backfill_progress ADD COLUMN IF NOT EXISTS attempted_until date` (idempotent); get_backfill_progress SELECT + trả thêm attempted_until; set_backfill_progress thêm param attempted_until=None + UPDATE cột.
- scripts/backfill_universe.py backfill_one: skip đổi từ `last_done_date >= to` → `attempted_until >= to` (NULL thì không skip); sau fetch: last_done = max(bar.ts.date()) nếu có bar, giữ nguyên nếu rỗng; ghi attempted_until = to.
- tests/test_backfill_universe.py (MỚI, 5 test).

4) Test quan trọng nhất (tự bịt miệng) — test_not_skipped_when_attempted_until_below_to: progress cũ ghi last_done_date = 08-10 nhưng attempted_until = None (mô phỏng dòng nói dối) → lần chạy kế tiếp KHÔNG skip, gọi API lại. Test này nằm trong 5 test, đã xanh.

Các test phủ đủ 4 ca plan yêu cầu: bar tới X < to → không ghi to; rỗng → không tiến; lần sau không skip mã chưa đủ; đủ dữ liệu → vẫn ghi to + skip lần sau (test_full_data_still_records_to_and_skips_next_time).
